# 开场结束与跳过开场的阵列入口

2026-09-21。用户要求：跳过开场也使用完整开场的阵列展开；完整开场结束后停留在档案阵列，不自动打开详情。

## 行为

- 普通开场在应用时间 26.56 秒结束（原片 31.56 秒），此时选中卡片轻抬约 0.4，尚未开始详情抽取。
- “进入系统”、触摸进入、Esc/Enter 跳过及直接阵列入口，提前跳到已有阵列序列的 21.9 秒。
  以 2 倍速度播放至 26.56 秒，约 2.33 秒完成；复用原有镜头、阵列入场、波浪与轻抬。
- 若阵列序列已经开始，从当前时刻接续；重复跳过不重启。已过终点则直接交给浏览模式。
- 进入期间保持 boot 模式的输入隔离，结束后恢复阵列交互并把键盘焦点交给读取按钮。
- 减少动态效果不播放展开序列。正文深链仍直接进入对应详情。
- `time` 或 `review=1` 的显式逐帧对照继续保留原片抽取/检视时间轴，不改变参考验证入口。
- 正常开场的时间上限在渲染前截断，因此后台恢复也不会误触发旧的 35 秒自动打开详情。
- 加载界面淡出前不会提前消耗精简入场时间；后台恢复不快进跳过整个展开段。

## 入场终点与浏览构图一致（2026-09-21）

原因：正常入场复用了原片固定 1920×1080 舞台和有限五列窗口，结束后才切换自适应舞台、循环可见窗口及交互镜头。16:9 下选中卡片仅约 1px 差异，但非标准比例的视野与中心变化、两侧补列会造成明显交接跳变。

修复：2D 开场继续使用原片舞台；正常 3D 展开开始时切到浏览布局，入场全程使用同一循环窗口及居中坐标。展开的收束阶段对齐共用的响应式浏览镜头、视野和指针偏移，最后一帧已经处于浏览构图。完整开场与跳过开场共用此路径。显式 time/review 原片对照保持原有时间轴与有限阵列。

验证：`reference/boot-handoff-check.html` 使用真实 WebGL 场景，分别在 1920×1080、1440×1080、2560×1080、390×844 下检查交接后连续 120 帧的卡片投影、FOV、可见阵列窗口及坐标原点；1455 项数值检查通过（另逐帧检查窗口不变）。既有参考时间轴交接回归保留。真实 `/?scene=archive` 入口到达 archive/desktop 状态。`npm run build`、`npm run check:viewport`、5 项 archive-entry 时间控制测试通过。此为桌面 WebGL 尺寸检查，不代表 iPhone 实机验证。
