# 完整开场结束时阵列横移修复

2026-09-21，codex/rhine-blog。本分支仅本地提交。

## 原因与复现

应用时间 35 秒，`bootFrame()` 从原片时间轴切入交互详情。开场使用原始阵列坐标
（`trackX = 0`），交互使用以选中列为中心的坐标（`trackX = columnCamera.value`）。
当前文章位于第 0 列，因此列偏移为 -10.4。此前只改变了模型/阵列坐标，摄像机仍从旧坐标缓动追赶，
形成一次额外的大幅横移。这与首次 GPU 初始化的卡顿是两个不同问题。

同一实际页面逐帧记录：

| 时刻 | 档案世界 X | 相机 X | 档案左上角投影 X |
| --- | --- | --- | --- |
| 修复前，开场最后一帧 | -10.4 | -32.8320 | 618px |
| 修复前，详情第一帧 | 0 | -30.0559 | 1972px |
| 修复后，开场最后一帧 | -10.4 | -32.8320 | 618px |
| 修复后，详情第一帧 | 0 | -22.1289 | 585px |

帧间隔不同，不能将两次缓动增量直接视为性能对比。关键是切换时阵列原点变化 10.4，
相机也必须在同一帧同步变换坐标；不能让相机用动画追赶这个坐标变换。
正常的后续响应式镜头构图继续沿用，不改变原片中的抽取高度、波浪或卡片运动轨迹。

## 修复与验证

`ArchiveScene` 记录上一帧是否来自开场时间轴。仅在从时间轴切入交互时，把相机位置和观察目标
同步减去列偏移，然后再运行既有镜头插值。预热恢复该标记，直接打开详情不会误用补偿。
进入交互后标记不再触发重复补偿。

回归页：`/reference/boot-handoff-check.html`（仅本地开发服务）。
该页实例化真实 `ArchiveScene`、加载实际模型，检查：

- 预热后初始镜头保持不变，直接进入详情不补偿。
- 时间轴进入详情/阵列/重播后再次进入详情时，相机收到同一原点偏移。
- 重复设置同一模式不重复补偿。
- 交接前后相机与档案的横向相对位置连续。

实际浏览器运行 11 个断言全部通过。原页面帧采样也确认不再跳到屏幕外。
